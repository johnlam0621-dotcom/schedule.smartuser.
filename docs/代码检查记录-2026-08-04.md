# 代码检查记录（2026-08-04）

## 已修复

- 后端按角色限制接口，防止用户绕过前端菜单直接访问无权限功能。
- Manager 不能创建、提升、修改或重置 Admin，避免权限升级。
- 用户、菜单、权限页面会显示后端错误，不再静默失败或误报保存成功。
- 预约只能使用 Google Sheet 同步进来的空白时段；改期也必须重新选择真实空位。
- 预约空位使用数据库原子更新，避免两个人同时预约同一个时段。
- 改期后同步原时段和新时段到 Google Sheet，并检查 Sheet 行是否已移动。
- 日期输入使用澳洲本地日期，避免早上因 UTC 转换显示前一天。
- 启动脚本自动寻找 Node.js，并可同时启动前端和后端。
- 示例配置已移除真实密码和密钥；本机配置保存到被 Git 忽略的文件。
- 登录页不再预填默认账号和密码，只显示空白输入框。
- Book 页面修复产品复选框布局，并显示数据库中真正可预约的 Google Sheet 日期；未导入目标周时会明确提示。
- Book 新预约回写 Sheet 时把数据库 `Fixed` 映射为下拉框允许的 `NEW CRM`，避免 B 列数据验证拒绝更新。
- Week 导入改为批量 SQL，避免远程 MySQL 逐行插入造成数分钟等待。
- 修复 Apps Script POST 302 重定向：后端保留 Location，再使用 GET 读取最终 JSON，不再出现空响应或 404。
- 禁止 CSV/Excel 导入、手动同步和无来源预约向业务排班 Sheet 批量追加数据库格式行。
- Google Sheet 完全作为只读数据源：允许列出 Week、预览和导入数据库，但预约、取消、改期和文件导入都不会回写。
- 后端已删除 Apps Script/Sheets API 的追加写入实现；预约写入入口固定返回 skipped，不发出网络写请求。
- Redis 不可用时登录会话使用 MySQL `sys_auth_session` 持久化，后端重启后仍能恢复登录。
- 管理员初始化改为显式强密码环境变量，不再在源码、SQL 或验证脚本中保存弱默认密码。
- 新增 Google 重定向、禁止追加、会话恢复和管理员初始化自动化测试，共 5 项测试通过。

## 需要外部配置或人工确认

- Google Apps Script 新版本需要在“脚本属性”中设置 `SYNC_SECRET`，然后重新部署 Web App。
- 截图中的错误第 216 行属于旧版批量追加产生的数据；删除该行前必须由业务人员确认。
- Google Maps 的 Maps JavaScript API、Geocoding API 和 Routes API 必须在同一个项目启用，并设置正确的 HTTP referrer。
- 以前出现在源码或聊天记录中的数据库密码、Google 同步密钥和 Maps key 建议全部轮换。
- 业务周当前以 `Week 388 = 2026-07-27` 为基准。如果新年度周编号重置，后端和路线地图前端都要更新基准。

## 每次更新后的回归检查

1. 使用 Admin、Manager、Scheduler 各登录一次，确认菜单与接口权限一致。
2. 刷新 Google Sheet 标签，选择不同 Week，预览后再导入数据库。
3. 在 Book 页面选择日期、地址和产品，确认只显示 Sheet 中真正空白的时段。
4. 连续尝试预约同一空位，第二次必须失败，不能覆盖第一次预约。
5. 在 Routes map 选择不同 Week 和 Day，确认记录、统计和地图标记同时变化。
6. 修改或改期预约后，检查 Google Sheet 原行和新行都已正确更新。
